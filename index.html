⚡ Webhook AbaFusion
NON TESTÉ
Envoi HTTP POST réel (fetch) vers l'URL de ton webhook. Si l'envoi échoue, le message d'erreur exact s'affiche pour diagnostiquer (CORS, URL invalide, serveur down…).
Proxy public déjà en ligne, actif immédiatement. Pour ta propre URL fiable (recommandé pour de la production), déploie webhook-proxy-worker.js sur Cloudflare Workers (gratuit, 5 min) et remplace la valeur ci-dessus par https://ton-worker.xxx.workers.dev/?url= — garde bien le ?url= à la fin.
StatutEn attente
Pourquoi ça échouait avant : la plupart des échecs viennent soit d'une URL de webhook expirée/désactivée côté AbaFusion, soit du serveur qui refuse les requêtes cross-origin (CORS) envoyées depuis un navigateur. Ce module fait un vrai appel réseau et t'affiche l'erreur exacte renvoyée — copie-la pour vérifier côté AbaFusion. Pour un test rapide sans compte, remplace l'URL par une URL webhook.site : ça te confirme que l'envoi lui-même fonctionne.
📟 ESP32 — USB uniquement
Connexion filaire USB directe (Web Serial) — 100% hors-ligne. Aucune IP, aucun Wi-Fi, aucun Bluetooth.
Mode alerte automatiqueOFF
En mode alerte activé, le firmware ESP32 déclenche lui-même la LED rouge + l'alarme dès qu'un vrai passage est détecté par le capteur IR — sans intervention du téléphone.

🔴 ESP32 sans Wi-Fi, USB uniquement : cette carte ne se connecte à aucun réseau. Un appui sur le bouton BTN1 (à côté du logo Wi-Fi imprimé) envoie juste un signal par le câble USB — c'est le téléphone, avec sa propre connexion internet (Wi-Fi/4G), qui envoie réellement à AbaFusion à ce moment-là. Ça marche donc uniquement si le téléphone est connecté à internet ET l'ESP32 branché en USB avec cette page ouverte. Aucun CORS possible ici puisque tout passe par USB + le proxy déjà configuré dans l'onglet AbaFusion. Limite matérielle : si le capteur température n'est pas détecté au démarrage (message série "TEMP_SENSOR:NON_DETECTE"), vérifie le branchement I2C (SDA/SCL). Limite navigateur : Web Serial fonctionne sur Chrome/Edge desktop et Android — pas sur Safari/iOS.

🎥 Scan facial (caméra réelle)
CAMÉRA INACTIVE
Utilise la vraie caméra de l'appareil. La détection de présence d'un visage utilise l'API native du navigateur quand elle est disponible.
Ce que fait réellement ce module : il capture une vraie photo via ta caméra et détecte si un visage est présent dans le cadre (liveness basique). Ce qu'il ne fait pas : il ne reconnaît pas l'identité d'une personne parmi plusieurs (ça demanderait un moteur de reconnaissance faciale entraîné + une base de visages de référence, hors de portée d'une page web seule). Si tu as besoin de vraie identification 1-vers-N, il faut un service dédié (AWS Rekognition, Azure Face, etc.) — dis-le-moi et je peux préparer l'intégration.

Vraiment réel : ce module déclenche le capteur physique de ton appareil (Touch ID / Face ID / Windows Hello / empreinte Android) via WebAuthn — le système d'exploitation gère la vérification biométrique, personne (ni moi ni la page) n'a accès à tes données biométriques brutes. Nécessite HTTPS et un appareil avec capteur biométrique. Pour une vraie production, la vérification cryptographique finale doit se faire côté serveur — ici la démo confirme le succès au niveau du navigateur.
🎫 Scan de ticket (caméra réelle)
INACTIF
Scanne un vrai QR code / code-barres via la caméra pour valider un billet.
Réel : la lecture QR/code-barres utilise l'API native BarcodeDetector du navigateur (Chrome/Edge) sur le flux caméra en direct. Les codes valides de démonstration sont SAFE-0001, SAFE-0002, SAFE-0003 (stockés en local) — un code scanné une seconde fois est signalé "déjà utilisé". Ajoute tes vrais codes de billets dans la fonction validTicketCodes du script, ou connecte ta billetterie via le webhook AbaFusion pour une vraie base à jour.
📣 Communication — Presse
Envoi réel via WhatsApp (ouvre une vraie conversation) et par email.
WhatsApp : ouvre une vraie conversation WhatsApp (app ou web) avec le numéro et message pré-remplis — l'envoi final se fait d'un vrai clic dans WhatsApp, comportement normal et volontaire (aucune app tierce ne peut envoyer un WhatsApp à ta place sans ton clic). Email : ouvre ton vrai client mail (Gmail, Outlook…) avec le message prêt à envoyer. Synchronisation AbaFusion : chaque envoi WhatsApp ou email est automatiquement transmis à AbaFusion — via l'ESP32 en USB s'il est connecté (aucun CORS), sinon via le webhook/proxy du navigateur.

RÉEL

🔒 Option 2 — Chiffrement (AES-256)
RÉEL
Protège le contenu — réversible uniquement avec le bon mot de passe.
Réel : SHA-256 et AES-256-GCM = API native Web Crypto, pas une simulation. Sécurité : le texte en clair n'est jamais envoyé — seulement le hash ou le chiffré. Limite technique honnête : WhatsApp/email ont une limite de longueur de message — si le contenu chiffré est trop long, seul un extrait + la mention "texte complet envoyé à AbaFusion" partent par ces deux canaux ; AbaFusion, lui, reçoit toujours l'intégralité. Mot de passe perdu = contenu irrécupérable, pour tout le monde.
